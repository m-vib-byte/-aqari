# أرشفة ملف PDF الأصلي — AQARI V267

هذه دفعة تطوير على PR #75. بقيت بوابة الإصدار **HOLD**؛ لم يحدث نشر إنتاج أو تعديل بيانات مستضافة في هذه الدفعة. التفويض بالنشر قائم بعد استيفاء الشروط ولا يحتاج تجديدًا.

## ما تغير فعليًا

- يحفظ `private.aqari_official_pdf_artifacts` بايتات أول ملف صادر من المحرك لكل إصدار، وبصمتها وبصمة اللقطة والمستخدم ونسخة المحرك. لا تعديل أو حذف عبر التطبيق؛ يصدر التصحيح كسجل إصدار مستقل.
- `aqari_official_pdf_commit` متاح للخادم الموثوق فقط. يعيد فحص عضوية طالب التنزيل ونطاق العقار، ويربط الملف بالإصدار الصحيح، ويتحقق من الحجم والبصمة، ويسجل أول أرشفة في التدقيق. لا يستطيع JWT المتصفح رفع PDF اعتباطي لهذا الأرشيف.
- `aqari_official_pdf_get` يعيد الملف للمستخدم المخول. واجهة التصدير تتحقق من الهوية وتقرأ اللقطة والملف ثم تعيد فحص الصلاحية. لا يعاد توليد PDF إذا سبق حفظه، حتى بعد ترقية المحرك.
- انقطاع الرد بعد الحفظ يعالج بإعادة القراءة. لا تُسلّم بايتات مولدة دون إثبات وجودها في الأرشيف. لا يستبدل الطلب المتكرر الملف السابق.
- تتحقق الواجهة من بصمة البايتات، وتوضح إلغاء المستند في الاسم والرسالة مع إبقاء الأصل ثابتًا. تغلق طلب التنزيل عند إغلاق النافذة، وترفض النتائج المتأخرة أو تغير الحساب. أخطاء رفض الصلاحية تصل إلى منطق إفراغ البيانات الخاصة.

## أدلة منفذة محليًا

- 945 اختبار JavaScript ناجح، دون فشل أو تخطي، بعد الحفاظ على إصلاحات فرع التطوير الأحدث. تشمل تشغيل واجهة التنزيل والتاريخ ورفض البصمة المختلفة والإلغاء وإغلاق الطلب المعلق.
- 23 مجموعة قبول/رفض SQL ناجحة في PostgreSQL/PGlite معزول في الذاكرة. المجموعة الجديدة تختبر الحفظ والاسترجاع الفعليين، منع التعديل والحذف، منع الكتابة من المتصفح، نطاق العقار، التكرار، الإلغاء وسحب العضوية. بياناتها اصطناعية وتُرجع المعاملة؛ ليست نسخة من الإنتاج.
- 20 اختبار Python ناجح: 13 لاختبار مسار الأرشفة و7 لمحرك PDF. اختبار الأرشفة يولد PDF حقيقيًا، يحفظه في محاكاة النقل ويعيد بايتاته بعد تبديل المحرك. اختبار SQL مستقل يثبت ضوابط قاعدة البيانات؛ لا تُخلط المحاكاة باتصال مستضاف.
- CI القديم عند `5e0e241612a32d1540f12d7e37bd9154389b2516`: نجحت 8/9 فحوص. توقف Preview E2E عند HTTP 401 قبل تشغيل التطبيق. هذه نتيجة ذلك SHA فقط، وليست قبولًا للتغيير الجديد.

إعادة التنفيذ محليًا: `node --test tests/*.test.cjs tests/*.test.mjs`، و`npm run test:completion --prefix staging-database/local-test`، و`python -m unittest discover -s tests -p 'official_document_*test.py' -v`. لا يقبل مشغل SQL رابط قاعدة مستضافة.

## الإعداد المستضاف المطلوب وحدود الاكتمال

1. تطبيق `official-document-pdf-archive.sql` بعد `official-document-access-hardening.sql` على قاعدة تم التحقق من هويتها وأخذ نسخة منها أولًا؛ ثم اختبار القبول والرفض عليها. لم يطبّق هنا.
2. إعداد `AQARI_PDF_ARCHIVE_SUPABASE_URL` مطابقًا لقاعدة النسخة و`AQARI_PDF_ARCHIVE_SERVICE_KEY` في بيئة الخادم فقط. لا توضع قيمة المفتاح في المتصفح أو المستودع أو المحادثة. تستخدم الدالة مفتاح Supabase السري الحديث، وتقبل مفتاح الخدمة القديم إذا طابقت هويته المشروع. عند غياب الإعداد يعاد 503 واضح دون تسليم ملف غير مؤرشف. [توثيق المفاتيح الرسمي](https://supabase.com/docs/guides/getting-started/api-keys).
3. الأرشفة تتم عند أول تصدير، وليست جزءًا ذريًا من معاملة إصدار المستند بعد. لا يدعي هذا استرجاع بايتات تاريخية لم تحفظ أصلًا. المستند الملغى دون PDF محفوظ لا يولَّد له أصل جديد. لذلك يبقى البند 69 جزئيًا حتى استكمال الأرشفة وقت الإصدار وقبولها مستضافًا.
4. الأصل لا يعاد ختمه عند الإلغاء لأن ذلك سيغيّر بايتاته. تُعرض حالة الإلغاء في السجل واسم التنزيل؛ يلزم نموذج إلغاء مستقل إذا أريدت نسخة تحمل الختم. لم تغط هذه الدفعة بقية نماذج المعاينة والصور والتوقيعات أو المطابقات الافتتاحية والتجارية.
5. اختبار متصفحات فعلية وأجهزة iPhone/iPad/Desktop، حفظ الملف وطباعته، إعداد المزودين، النسخة الكاملة Database/Auth/Storage، الاستعادة المعزولة ونقطة الرجوع V266 ما زالت شروطًا غير مثبتة. الأرشفة الجديدة ليست نسخة احتياطية للنظام.
