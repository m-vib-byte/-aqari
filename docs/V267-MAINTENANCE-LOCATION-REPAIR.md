# إصلاح موقع طلب الصيانة — 2026-09-09

كان عرض العقار والوحدة يعتمد على `aqari_leases.snapshot`. دور الصيانة ممنوع عمدًا من قراءة العقود، ولذلك كان الطلب يظهر دون موقع رغم صحة صلاحية قراءة الصيانة.

أصبحت الواجهة تقرأ اسم العقار ورقم الوحدة الحاليين من `aqari_maintenance_locations`، لطلبـات الصفحة الحالية فقط، دون تحميل العقد أو رقمه أو المبالغ الموجودة فيه. يرجع المسار `request_id` لربط الطلب بالموقع و`property_name` و`unit_no` فقط. بقي اسم المستأجر، حين تسمح به صلاحيات المستخدم، تحت سياسة قراءة جدول المستأجرين القائمة.

يفحص المساعد الخاص هوية المستخدم وصلاحية الصيانة وتخصيص العقار. الحد 50 معرفًا فريدًا؛ أي معرف مفقود أو من مساحة أو عقار آخر يرفض المجموعة كلها بالرسالة نفسها. الدالة العامة تعمل بصلاحيات المستدعي، والمساعد المحدود فقط يعمل بصلاحيات المعرّف داخل `private`، مع مسار بحث فارغ ومنع التنفيذ العام والمجهول. لم تتغير سياسات العقود أو صلاحيات البيانات التجارية.

رفض قراءة الموقع أو فقد الجلسة يمسح الصفوف والمسودات الخاصة. كذلك يُمرر رفض الصلاحية الأصلي أثناء تحديث الصيانة أو إعادة قراءته، بعد مسح البيانات، كي يغلق مكوّن الحوار عند 401 أو 403 أو 42501 أو ACCESS_DENIED. تعطل الخدمة المؤقت أو الرد غير المكتمل يحافظ على الصفحة والمسودات دون تأكيد قراءة جديدة. تبقى تحديثات الحالة والتكلفة مشروطة برقم المراجعة مع إعادة القراءة، ويظل الحفظ غير المؤكد، بما فيه تعطل 503، مقفلاً حتى استرجاع المحفوظ صراحة.
