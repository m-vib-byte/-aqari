# مراجعة الإخلاء والمستندات — تقرير تنفيذ مشروط

تاريخ الفحص: 2026-09-09. لا تمثل هذه الوثيقة اعتماد إطلاق أو إقرار اكتمال سجل المتطلبات. تفويض النشر على myaqari.com قائم بعد اجتياز شروط المالك، دون طلب موافقة جديدة.

## التنفيذ

- طلب إخلاء بإصدارات محفوظة ومراجعات للإيجار والتأمين والخدمات والصيانة والمفاتيح والملاحظات. تحفظ كل مراجعة هوية منفذها ولقطة بيانات العقد والمدفوعات المؤكدة ورصيد دفتر التأمين. التكرار بعد انقطاع الاتصال لا ينشئ إصدارًا جديدًا، والتعديل المتزامن يُرفض.
- طلب المراجعة لا يصدر براءة ذمة ولا ينهي العقد أو يعلن الرصيد النهائي. يتعايش مع وحدة التسوية النهائية المضافة بالتزامن على الفرع؛ لم يُستبدل تنفيذها.
- إصلاح طباعة التسوية النهائية لتستمد الأسماء وأرقام العقد والعقار والوحدة من اللقطة المحفوظة مثل الأرصدة. اختبار انحدار يثبت أن تغيير بيانات المصدر لا يغير المستند التاريخي.
- رفع الأصل دون ضغط لملفات PDF وJPEG وPNG وWebP حتى 10 ميجابايت، مع فحص ترويسة الملف، ومطابقة البصمة، وإعادة قراءة التصنيف والمالك والسجل بعد الحفظ. اختيار تصنيف عقد موقع إجراء صريح؛ صور الإشعارات أو الشيكات لا تتحول تلقائياً إلى عقد موقع.
- دعم 21 تصنيفًا تفصيليًا يغطي هويات المالك والمؤجر والمستأجر، السجل التجاري والوكالة، الملكية والمخططات، اشتراكات وفواتير الكهرباء والمياه والغاز والإنترنت، العقد والملاحق وسند القبض والشيك والتحويل، معاينة الإخلاء وبراءة خدماته وإشعاره والتصفية الودية وفواتير الأضرار. يدعم الماسح الحالي أيضًا التصنيفات المضافة بالتزامن وPDF/DOCX. لا يستنتج النظام صحة التوقيع أو السداد من مجرد رفع ملف.
- واجهة طلب المراجعة مترجمة إلى خمس لغات. واجهة رفع الأصول التفصيلية بالعربية حاليًا؛ لا تعني هذه الدفعة اكتمال الترجمة أو OCR أو التحقق من صحة الوثيقة.

## نتائج يمكن إعادة إنتاجها

- `node --test --test-reporter=tap tests/*.test.mjs tests/*.test.cjs`: 740 اختبارًا ناجحًا، صفر فشل أو تخطي.
- `npm test --prefix staging-database/local-test`: نجحت مجموعات SQL الإحدى عشرة: نطاق الموظف، المالية، التأمين، اعتماد الموظف للعقود، مواقع الصيانة، قائمة التسويات، التسوية، المستأجر المستورد، التذكير، مراجعة الإخلاء، وتصنيفات المستندات. تُستعاد بنية اختبار محلي معزولة؛ هذا ليس اختبار استعادة قاعدة الإنتاج وملفاتها.
- على فرع Supabase المستقل `ofgmcsmxmdswlovsckqs`: طُبق سجل المراجعة والتصنيفات، ونجح اختبار المراجعة واختبار حجز الأنواع الـ21 والتحقق من السجلات والتصنيف والعزل. كل البيانات اصطناعية ومعاملاتها متراجَع عنها. تحقق لاحق: صفر مستخدمين وعضويات وعقود ومراجعات ومستندات وملفات Storage.
- لا رفع أصلي حي عبر حساب مستخدم في هذه النتائج. اختبارات واجهات المراجعة تستخدم DOM اصطناعيًا؛ ليست قبول أجهزة.
- صححت تهيئة اختبارات واردة من تحديث متزامن: تحديد workspace قبل التحول للدور المقيد، وإنشاء مستأجر اصطناعي مستقل بدل الاعتماد على بيانات موجودة، وحصر إنشاء بيانات Storage الاصطناعية في مساعد مؤقت. لم تُمنح صلاحيات تطبيق أوسع لإنجاح الاختبارات.

## شروط الإطلاق التي ما زالت مفتوحة

1. المتصفح السحابي تعذر عليه إنشاء جلسة CDP مستقرة ثم فشلت محاولة الاسترداد الموثقة. ليست هذه نتيجة فشل للموقع نفسه. يلزم متصفح عامل وحسابات اختبار فعلية بالأدوار المطلوبة، ثم الدخول والحفظ وإعادة الدخول والصلاحيات والعقود ومعاينة الطباعة.
2. لا يتوفر دليل اختبار على أجهزة iPhone وiPad فعلية أو مخرجات الطباعة. يلزم تنفيذ الحالات على الأجهزة أو إتاحة بيئة أجهزة حقيقية مع توثيق النتائج.
3. لا تتوفر في هذه الجلسة وسيلة نسخ كاملة موثقة لقاعدة الإنتاج وحسابات Auth وبايتات المرفقات، أو بيئة استعادة لها. يلزم الوصول التشغيلي للنسخ وتخزين نسخة مشفرة واستعادتها والتحقق من تطابق البيانات والملفات والمعاملات.
4. إصدار V266 السابق والنسخة الحالية يرتبطان بقاعدتين مختلفتين بحسب الأدلة السابقة؛ تحويل النطاق وحده لا يحفظ رؤية المعاملات الحديثة. يلزم اختبار خطة رجوع للتطبيق متوافقة مع البيانات الحالية، مع إجراءات موثقة لحماية المعاملات أثناء الرجوع.
5. التسوية النهائية تحتاج حسم واختبار سياسة احتساب الإيجار لفترة الإخلاء الجزئية ونهاية العقد والبيانات المستوردة، وتسوية الخدمات والأضرار بمستنداتها، وربط إنهاء العقد وشغور الوحدة. كما يلزم مراجعة حدود قراءة البيانات المالية وصلاحية إعادة الطباعة بعد سحب الإذن. لا يغلق وجود النموذج هذه البنود.
6. التكاملات الخارجية والقبول الكامل لبقية البنود الـ155 لم يثبت اجتيازها. لا يوجد موعد إنجاز مؤكد قبل إتاحة موارد الاختبار والنسخ وحسم هذه الفجوات.
