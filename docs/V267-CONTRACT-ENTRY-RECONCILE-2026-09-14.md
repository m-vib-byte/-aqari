# AQARI V267 — مصالحة مدخل العقود القديم مع المسار المحمي

التاريخ: 14 سبتمبر 2026. هذا تغيير Preview فقط فوق رأس PR #159 الأصلي `6a1cb4574b98309ef3a9030bc3c0f9fbf93f1b33`، ولا يغيّر `main` أو Production أو `myaqari.com` أو مرجع V266 التاريخي.

## ما تمت مصالحته

تم أخذ الجزء الضيق غير المتعارض من خط الدعم المتزامن الخاص بتوجيه مدخل العقود فقط، دون دمج فرع PR #116 أو PR #157 المتعارضين ودون استبدال ملفات المستأجرين أو الموظفين أو المالية أو الأدلة الحالية.

- المسار القديم `smartContractsPage` ومسار `leases` يمران الآن عبر مدخل AQARI V267 نفسه بدل الرجوع إلى مصنع العقود القديم.
- مدخل العقود يعيد التحقق من جلسة المستخدم وصلاحية قراءة قسم العقود قبل التحميل الكسول للصفحة، ثم يقارن نطاق الجلسة ويعيد فحص الصلاحية بعد اكتمال التحميل وقبل فتح الصفحة.
- اختصار العقار يستطيع تمرير نية الإنشاء والعقار إلى المدخل الموحد عبر `AQARI_V267_OPEN_CONTRACTS` دون تغيير سلوك أي تنقل آخر.
- الاختبار المركز يثبت التوجيه، إبقاء التنقل غير المتعلق بالعقود كما هو، ووجود حارسي النطاق/الصلاحية حول التحميل.

## حد الإثبات

صفحة العقود الحالية في خط الإصدار تستقبل `initial` في توقيع `openRentalContracts(initial={})`، لكن هذه الدفعة لا تدعي أن جميع قيم `initial`، مثل فتح نموذج الإنشاء مباشرة أو اختيار العقار تلقائياً، أصبحت مستهلكة داخل الصفحة. لذلك لا يُغلق بها قبول رحلة «اختصار العقار → عقد جديد» ولا أي بند من 155 وحدها. الهدف هنا إزالة الرجوع غير المحمي للمسار القديم وجعل كل مداخل العقود تمر من بوابة صلاحية واحدة.

اختبار Vercel Preview يشغل `tests/v267-contract-entry-routing.test.mjs` على نفس الشجرة. نجاح البناء أو READY يبقى دليلاً برمجياً فقط، وليس قبولاً مستضافاً بحساب فعلي أو اعتماداً للأجهزة أو الإنتاج.

تبقى بوابة المالك بتاريخ 13 سبتمبر 2026 نافذة بالكامل: 155/155 بدليل، CI أخضر على نفس SHA، قبول Preview بالحساب الحقيقي، Desktop وiPhone وiPad فعليان، نسخة Database/Auth/Storage كاملة تشمل بايتات المرفقات، استعادة مستقلة، رجوع مجرب يحفظ المعاملات، إعداد Production الصحيح، الاختبار النهائي للمالك ثم موافقته الصريحة اللاحقة على نفس SHA قبل أي دمج أو نشر إنتاجي.
