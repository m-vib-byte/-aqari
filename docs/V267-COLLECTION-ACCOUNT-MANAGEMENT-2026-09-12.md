# تعديل وأرشفة الحسابات والصناديق — 12 سبتمبر 2026

الحالة: تنفيذ واختبارات محلية معزولة. لا يوجد تطبيق لهذه الترقية على قاعدة مستضافة أو نشر إنتاجي في هذا الدليل.

## التغيير

السجل السابق ينشئ حساب البنك أو الصندوق ويرحّل الوصل إليه، لكنه لا يتيح تصحيح اسم الحساب ومرجعه أو أرشفته بسجل تدقيق. أضيفت ترقية مستقلة قابلة لإعادة التطبيق، دون إعادة تعريف RPC السجلات المالية المشترك أو تغيير قواعد الإقفال وترحيل التحصيل فيه.

[ترقية SQL](../staging-database/sql/collection-account-management.sql) تضيف رقم مراجعة وبيانات آخر تعديل للحساب، وسجل عمليات خاصًا غير قابل للتعديل أو الحذف. يسمح المدير بتصحيح الاسم والمرجع المحجوب أو الأرشفة مع سبب واضح ومراجعة حديثة، ويُرفض تغيير معرّف الحساب أو العقار أو نوعه أو عملته. لا يوجد استرجاع تلقائي لحساب مؤرشف، ولا حذف أو إنشاء رصيد مالي.

الكتابة تتطلب تحقق AAL2 وتستعمل قفل صف `aqari_app_state` نفسه المستخدم بترحيل الوصولات وإقفال الفترات، ثم تقفل صف الحساب. بذلك تُسلسل الأرشفة مع الترحيل، ويمنع Trigger مستقل إضافة ترحيل جديد للحساب المؤرشف حتى من مسار آخر، مع استمرار رفض المسار المالي الأصلي له.

لكل تعديل `operation_id` ثابت وطلب موثق. إعادة الطلب المطابق تعيد نتيجة العملية المحفوظة دون رفع المراجعة مرة أخرى، أما تغيير محتواه أو إعادة استخدام مراجعة قديمة فيُرفض. إعادة طلب تعديل قديم بعد الأرشفة لا تعيد تنشيط الحساب.

تبقى جميع حقول الوصولات والترحيلات السابقة دون تعديل. يحتفظ جدول مستقل `aqari_collection_posting_accounts` بصورة بيانات الحساب للعرض التاريخي. بالنسبة إلى الترحيلات السابقة للترقية، تُلتقط بيانات الحساب المتاحة عند الترقية وتوسم `captured_on_post=false`؛ لا يدّعي ذلك معرفة اسم الحساب وقت ترحيل قديم. الترحيلات الجديدة تلتقط الاسم والمرجع والمراجعة وقت حفظها (`captured_on_post=true`). لا تستبدل إعادة تطبيق الترقية الصور المحفوظة.

## الواجهة والربط

[مكوّن إدارة الحسابات](../src/v267/components/collection-account-manager.js) يستخدم الحوار والجلسة الحاليين، ويعرض الحساب والعقار ونوعه ومراجعته، ونموذج تصحيح مختصر أو أرشفة مع إقرار منع الترحيلات الجديدة، وسجل الأسباب والجهة المنفذة.

```js
import {createCollectionAccountManager} from '../components/collection-account-manager.js';
const accountManager = createCollectionAccountManager(d, {
  onChanged: async () => { await load(); }
});
d.body.append(accountManager.el);
// بعد كل قراءة ناجحة للسجل:
accountManager.update(data);
d.onDispose(() => accountManager.clear());
```

يجب أن تستبعد خيارات ترحيل الوصل الحسابات التي `status !== 'active'`. تعيد عملية `list` في `aqari_collection_account_manage` أيضًا مصفوفة `posting_accounts`، تربط `posting_id` بصورة بيانات الحساب، ويمكن استعمالها في الأرشيف بدل الاسم الحالي للحساب.

فقد رد الحفظ يستدعي قراءة مستقلة للعملية باسمها الثابت. عند تعذر القراءة يحتفظ المكوّن بطلب مجمد ويمنع كتابة أخرى حتى التحقق. إذا أثبتت القراءة عدم تسجيل العملية وبقاء المراجعة نفسها، يسمح بإرسال الطلب نفسه مرة ثانية. وجود حدث تدقيق لا يكفي وحده للنجاح: تُطابق هوية الحساب والمراجعة والحقول المحفوظة أيضًا. تعذر تحديث لوحة أخرى بعد نجاح الإثبات لا يحوّل الحفظ المثبت إلى نجاح غير مؤكد.
