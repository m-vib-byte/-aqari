## القدرة المتاحة والعائق المتبقي

أدوات Supabase المتصلة تسمح بقراءة المشاريع والفروع والمخططات وSQL، لكن لا تعرض قراءة قائمة النسخ أو تنزيل نسخة DB أو نسخ بايتات Storage. لم يظهر منفذ إدارة عام مصادق عليه لهذه العمليات، ولم يوجد اعتماد نسخ مخصص في متغيرات البيئة التي فُحصت بالاسم فقط. لا تتوافر أدوات `supabase` أو `pg_dump` أو `pg_restore` أو `psql` أو `vercel` في PATH. تثبيت برنامج وحده لا يمنح صلاحية النسخ. أداة `restore_project` ذات معامل المشروع فقط ليست دليلاً على إمكانية اختيار نسخة ونقلها لهدف مستقل؛ لم تُستدعَ.

**العائق وصول تنفيذي للنسخ والتحقق من الاستعادة، وليس طلب تفويض جديد بالنشر.** لا تثبت هذه المراجعة غياب نسخ يديرها المزود؛ لم يمكن تعدادها. لا تُصدَّر صفوف Auth الحساسة إلى المحادثة ولا تُطلب كلمات مرور أو مفاتيح من المستخدم.

إغلاق الشرط يتطلب:

1. قراءة بيانات النسخ الحالية لكلا المصدرين، عبر قدرة مخوّلة على `GET /v1/projects/{ref}/database/backups` أو لوحة Backups، وتسجيل معرف النسخة ووقتها أو نافذة PITR. وجود Pro لا يثبت اكتمال نسخة بتاريخ مناسب.
2. تنفيذ نسخة DB وAuth مباشرة إلى وجهة خاصة محمية، مع نسخ ملفات Storage الأصلية وبصماتها وإعدادات الخدمة ومراجع الأسرار، دون إخراج قيمها إلى Git أو المحادثة. نسخ Supabase اليومية لا تشمل بايتات Storage. [توثيق النسخ](https://supabase.com/docs/guides/platform/backups).
3. استعادة الحزمة على هدف مستقل بعد منع المهام والاتصالات الخارجية فيه، ثم مطابقة أعداد السجلات والمجاميع والروابط والملفات، وتجربة حساب مخول والطباعة والجلسة، وقياس زمن الاستعادة والفروقات. الاستعادة إلى مشروع جديد تنقل DB وبيانات Auth، لكن Storage وإعدادات Auth ودوال Edge تحتاج معالجة مستقلة. [توثيق الاستعادة المستقلة](https://supabase.com/docs/guides/platform/clone-project).
