# مرشحا إصلاح التقييم والتواصل — 5 أكتوبر 2026

حزمة مراجعة، تعتمد على بنية التطبيق المستخرجة في PR #410. لا هجرة رسمية هنا،
ولم يطبّق شيء على Production أو Preview. جميع التجارب داخل PGlite وبصفوف اصطناعية.

## العطل المثبت والإصلاح

- سجل الإنتاج يحتفظ بمتغير `rating_year` يتعارض مع اسم العمود؛ يفشل إجراء التقييم.
  مرشح `../tenant-rating/candidate.sql` يستبدل فرع التقييم فقط بمنطق الأرباع المكتملة
  المعتمد في المصدر، ويزيل المتغير المتعارض. يبقى باقي السجل وصلاحياته دون تغيير.
- اختيار التواصل في السجل لا يعود بشكل موحد إلى المحرر؛ مصدر التوحيد القديم لا
  يطابق فرع الإنتاج. المرشح يعيد استخدام مصدري التفضيل والتوحيد بعد مطابقة بصمات
  الدوال، مع تكييف فرع التفضيل الفعلي. يحتفظ بقواعد الحساب، المراجعة، وعزل مساحة العمل.
- عمود `source_route` الجديد في التدقيق يبقى NULL للسجلات التاريخية؛ لا نخمن مصدرها.
  العمليات الجديدة تسجل المصدر الصحيح. حذف reconciliation الجماعي عند التثبيت مقصود:
  لا تغيير لتفضيلات أو موافقات أو رسائل حقيقية بمجرد تركيب المرشح.

الترتيب ملزم: مرشح التقييم ثم مرشح التواصل. كل مرشح داخل معاملة واحدة، ويتوقف
إذا تغير مصدره. الترتيب الخاطئ وإعادة التطبيق مرفوضان.

## التحقق

```sh
python3 scripts/build-production-contact-reconciliation.py
node scripts/verify-production-tenant-reconciliation.mjs
```

يُعاد إنتاج العطلين قبل الإصلاح، ثم تُشغّل سبع مجموعات قبول: التقييم، التواصل،
التخصيص التجاري، توافق المسارين، التحصيل المستقل، إدارة الحسابات، وMFA الحديث.
تثبت عينات مستقلة بقاء سجل تدقيق تاريخي دون تغيير أو اختلاق مصدر، وبقاء ACL
السجل العام ومنع الوصول المباشر للدوال الخاصة. Auth/Storage بدائل محلية، ولا
دفع أو إرسال أو قبول جهاز فعلي في هذه التجربة.

الملفات `history-before.sql` و`history-after.sql` fixtures محلية فقط؛ ليست هجرات.
بصمات المصدر في manifest لكل مرشح. يلزم قبل النشر الفعلي: النسخة الكاملة الحديثة
واستعادتها، تجربة تطبيق مستضافة، advisors ومراجعة الهجرات الرسمية.
